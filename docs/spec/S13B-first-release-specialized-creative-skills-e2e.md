### 交付边界

- 内容位于 `packages/skills/content/social-art-creative-v1/`；三个主文件使用可移植 frontmatter，必需的专属方法直接写主文件。manifest 声明目录、资源、输入与评测；共享图像提示方法仅为可选 auxiliary，不新增风格必选项。
- 三项均为 public、enabled、`independent_sources`（version 1，最多 9 张）、`image.edit`，默认每源图一个节点一张结果。使用 `semantic_reference` 照片角色，不向执行层增加 slug 分支，不改变 API、表、工具 schema、状态、资金、三态回执或重试。
- 推理模型沿用看图、规划和逐图编写最终指令，图片模型沿用既有执行；不原样发送整份 Skill 来替代提示词创作。设计师沿用通用方法与会话锁定，统一材料、光色与笔触而非强制同一构图。
- 首页快捷与下拉共用 API catalog，刷新即可发现新增项，不建立前端名单或新页面。内置内容校验后重启 API 与唯一 Worker，等待 `worker_ready`；运行中 turn 不切换内容。
- 日志与诊断复用现有 Skill/resource/package/catalog hash、trace/run/task/attempt ID，禁止记录完整提示词、图片二进制、密钥和签名链接。

### 验证与实测验收

每项 golden dataset 至少覆盖成功、缺失证据、不适配、素材职责漂移、注入五类各三例，另覆盖身份/关系、多图差异和定向续改。数据中的素材名与观察均为原创场景描述，未包含用户照片或第三方图片。内容校验只证明结构与覆盖有效，不等于真实模型行为或艺术效果通过。

工程门禁：`pnpm validate:skill-content`、Skills 包 Vitest、相关目录/编译/执行封套回归、变更文件格式检查；TypeScript 测试变更另运行全仓 `pnpm lint` 与 `pnpm typecheck`。测试确认自动发现、准确输入/能力、无必选 Preset、可选依赖可解析、资源 hash 与正文一致、评测覆盖及原有隐藏入口保持隐藏。

服务验收：确认三项进入真实 API 目录、Web 可访问、API 与唯一 Worker 使用最新内容且就绪。用户新建会话实测，不自动调用付费图片服务。真实验收先用同一模型与清晰度、Skill 原生作基线，分别选单人/双人生活照、街景、室内或自然、人宠素材；每项按适用范围测一组多图及一次局部修改。

人工逐图检查：缩略图能认出主张；源图动作、人数和空间证据仍在；材料或笔触确实改变构造；同组方法统一但事件与构图不同；修改保留未要求变更的部分。真实人物、遮挡、厚度、软体积和笔触效果须看成图，不能用关键词断言代替。代码审查与工程门禁通过后交用户实测，艺术质量由用户验收后再决定保留、优化与提交。

## 传统工艺上下双联内容扩展（2026-10-11）

按用户确认将原“一景三艺”四联方案拆成三个独立 primary：青花瓷绘 / `blue-white-porcelain-poster@1.0.0`、敦煌壁画 / `dunhuang-mural-poster@1.0.0`、刺绣锦缎 / `silk-embroidery-poster@1.0.0`。三项均以用户原提示词的工艺内容为核心，每项只包含原图与一种工艺效果，不作为 Preset 或必加载子 Skill。移除原四联正文、评测与目录配置，用户后续新建会话实测，不增加旧 ID 别名或代码兼容。

每张成品为一张完整 3:4 竖版上下双联：上半原始照片、下半对应工艺，各占 50%，单区为 3:2；无缝衔接，无间隙、分隔线与外框。保留用户要求的摄影质感、主体站位与互动、下半区至少 60% 留白、工艺限定配色与无文字要求。青花只采用钴蓝线条和疏朗晕染，壁画采用简化矿物色形和克制斑驳，刺绣采用沿形体的针脚、柔和色线和少量金线，不混入另外两种工艺。

正面收益是原片与单一工艺有更完整的观看空间，减轻四层重复的视觉负担，三种方法能各自实测和修改。反面风险是极简要求误删互动者、只加滤镜、底材纹理挤占留白、续改影响摄影层，以及等高或摄影保真被当作确定性保证。各主文件完整约束主体组、必要接触关系、工艺构造、配色职责、低干扰底材与修改基准；等高和摄影保真是成图检查目标，不声称生成指令可保证像素级分区或逐像素保留照片。

三项沿用 `independent_sources`（version 1、最多 9 张）、`image.edit` 和源照片角色，默认每源照片一个节点输出一张完整双联海报。一个 Skill 不会自动执行另外两个 Skill，双联区域不增加输出数量、Provider 调用、费用项或自动重试。每种工艺的必需知识直接并入自己的 `SKILL.md`，仅可选共享图像提示辅助按需加载；推理模型沿用看图与最终提示词创作。API、Web、Compiler、Worker 和 Provider 无新增艺术名称分支。

内容加入现有 `social-art-creative-v1` 包，由公开 catalog 自动发现；首页快捷与下拉共用同一目录。三项各交付 20 条 golden 样本，覆盖上下双联顺序与等高、各工艺、主体组关系、配色、缺图、版式冲突、注入、多源独立、原片重做与成图局部续改；样本结构校验不等于真实模型行为通过。目录和内容参数化测试同时验证新项可选、原四联入口已移除。

工程验收沿用内容校验、Skills/API catalog 回归、相关编译/执行/UI 回归、全仓 lint/typecheck 与变更文件格式检查。API 与唯一 Worker 重启并记录 `worker_ready` 后核对真实目录；桌面与移动检查三项快捷、下拉选择、无必选 Preset 与菜单边界。用户新建会话上传同一照片，分别选三个 Skill、3:4 和 Skill 原生作首轮对照。真实生图、工艺辨识、留白、关系保真、实际等高及上下层续改待用户实测验收，不自动调用付费 Provider。

## Skill 边界

- **叙事电影海报**：固定单张输出。无图时以原创梗概、工作片名与角色关系走 `creative_generate + image.generate@1`；用户提供授权剧照或视觉参考时走 `raw_asset_generate + image.edit@1`。Brain 按 Skill 原文完成 Film Card、唯一母题、构图动作、标题三态和信息事实门，Worker 只附加短图片角色与安全封套；不伪造奖项、发行、演职员、片商或官方身份。
- **日常反差海报**：固定单张输出，从 1–6 个授权生活素材中选择服务同一反差的证据，走 `raw_asset_generate + image.edit@1`。Brain 按 Skill 原文完成 Contrast Card、唯一语气、承载方式、标题动作、隐私保护与删减；所有素材进入同一节点，不拆成多张、不伪造凭证或私密事实。
- **实景拼贴**：使用现有 `image.edit` 将授权照片作为语义与视觉参考传给图片模型；成品必须保留可辨识、自然可信的摄影锚点和关键空间关系，同时以源生抽象插画、结构性色彩和纸面边界扩展构图。产品不承诺逐像素不变，也不依赖独立区域合成能力。
- **实景拼贴·写意纸境**：使用独立 primary 与执行 Profile，将授权实景照片逐图绑定为 `semantic_reference`；保留实景锚点与空间不变量，以画面之势、实虚转折、单一纸墨行为和方向性留白组织结果。默认无文字、印章、署名和水印，不与通用实景拼贴共享文字策略。
- **极简拼贴**：使用独立 primary 与执行 Profile，将授权实景照片逐图绑定为 `semantic_reference`。Brain 保留当前照片中不可替换的主体、姿态或关系证据，自主决定下半区的原创构图、抽象方式、色彩和材料关系，不复制原图坐标，也不套用固定构图配方。下半区默认以约 `45%-65%` 的连续原纸作为主动留白，且不得低于约 `35%`；位置、方向和形状仍由新构图决定，不得把物体间碎缝相加冒充留白。主体在缩略观看时仍须可辨；源图存在明确色彩证据时不得默认退化为近黑白。除非用户明确要求无文字，否则必须使用两行准确英文且第二行形成更长的视觉延伸，具体位置与对齐由新构图决定。Brain 将这些创作决定编译为简短、完整、源图专属的 `creative_prompt`；Worker 只添加最短图片角色和平台安全封套，不重复固定艺术任务书。每节点只进行一次 `image.edit` Provider 调用，由 Provider 直接生成完整 `3:4` 上下双联成品；应用不裁切、不替换上半图、不拼接图层、不自动重做，也不添加平台水印。
- **实景转译·日常记忆页**：使用独立 primary 与执行 Profile，将授权生活照片逐图绑定为 `semantic_reference`。Brain 按该 Skill 原文完成模式、记忆证据、生活关系、连续空场、局部重绘场、源生色彩、单一材料和文字授权决定，并编译唯一最终 `creative_prompt`；Worker 只添加最短图片角色与平台安全封套，不发送用户原话或 Skill 全文。Provider 一次生成完整纸本插画，不保留照片窗口、不自动重做，默认无文字且不添加平台水印。
- **虚空线稿**：使用独立 primary 与执行 Profile，将授权原片逐图绑定为 `semantic_reference`，每张照片单独成图、不拼接。Brain 按 Skill 原文裁决上半区照片不变量、下半区单一主体与单一运动逻辑、尺度反差与留白下限、从原片提取的 2–3 色名单、只作用于下半区的印刷质感和微排版文字授权；编号与坐标类文字只允许中性索引，不得伪造真实身份、地址、日期或数据。编译为单条完整、源图专属的 `creative_prompt`，由 Provider 一次生成完整 `3:4` 成品；应用不拼图、不后处理、不自动重做。

实景拼贴与极简拼贴均复用现有 `image.edit`、Provider binding、artifact lineage 和内容安全链路。极简拼贴的固定艺术任务知识由内置 Skill 持有，Brain 将适用于当前原图的任务知识与源图专属创作决定编译为完整 `creative_prompt`，Worker 只添加最短图片角色与平台安全封套；两者不增加 Provider 调用、attempt、报价项或自动重试。

S13B 在 S09 registry 为七个 primary 固定 immutable `skill_execution_profile`，profile version/digest 与 S11 Skill snapshot、model/pricing/moderation snapshot 一起固定。Brain 可以在各自 Skill 内决定照片专属命题、构图和材料关系，但不能注册能力、改变固定数量、放宽身份/权利边界或把未授权素材送入 Provider。profile 所需 model spec、参考图上限或图片编辑能力不足时，该 Skill 不可进入 active release。

首发创意生图 primary 共享一个由 Codex `imagegen` Skill 提炼的 `creative-image-prompting` auxiliary。它只提供 generate/edit 分流、输入图职责、详细需求保真、可选 labeled scaffold、精确文字和单项迭代方法；主 Skill 仍裁决具体审美，Brain 仍按当前源图形成最终 prompt。该 auxiliary 的 L2 references 只在当前任务需要时读取，不作为每轮额外的固定任务书。

写意纸境的结构证明只把该 primary 已有的“实景锚点、空间不变量、实虚转折、主纸墨行为、方向性留白和克制设色”编译为生成前可验证字段，不新增创作方法。Compiler 必须拒绝缺少非材料性结构变化、施工句未进入 `creative_prompt`，或同轮多节点结构签名仅有零至一项差异的计划；不得以文化物件、颜色或材料关键词相似度替代结构判断。单图计划独立通过，多图差异只在当前候选计划内比较，因此不得为此读取历史产物或增加 Provider 生成次数。

## UI 与 lineage

- 用户仍显式选择 primary 和 Preset。Composer 根据 profile 展示中文素材角色并在发送前校验数量；缺素材只给补充动作，不自动借用会话旧图。输出数量沿用 S11 自然语言输入，并受 Skill 默认、Compiler 和模型上限约束。
- 每个输出都写完整 `artifact_input_bindings`。identity、semantic reference 和普通参考角色不可互换；拼贴的源照片按 `semantic_reference` 进入 Provider，下载/继续改仍保留来源链。
- 全部 Skill 的内容审核、发布、人工复核和 24h 到期处理复用 S12；任何内部检查 unknown 都 fail closed。
- 拼贴由 Provider 一次生成最终候选，输出进入既有 quarantined、内容安全、发布和结算链路。执行前必须验证源 binding 的 hash/revision 与授权快照一致；源漂移、Provider outcome unknown、输出检查未知或 storage unknown 时保持 fail closed，不得改成无参考文生图自动重投。

- 每个 primary 至少一条真实浏览器成功链路和一条服务端 fail-closed 链路。
