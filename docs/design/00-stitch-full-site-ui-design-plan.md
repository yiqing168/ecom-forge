# Stitch 全站 UI 设计执行计划

## 1. 文档目的

本文定义 Ecom Forge 全站 UI 在 Stitch 中的设计方法、交付范围、生成顺序和评审门禁。它不替代 PRD、架构契约或 SPEC，也不授权提前实现尚未开放的阶段功能。

产品交互以 `docs/research/01-full-site-product-interaction-benchmark.md` 为依据，业务状态和接口分别以 `04`、`06`、`07` 及对应 SPEC 为依据。发生冲突时按 `docs/README.md` 的裁决顺序处理，不由 Stitch 生成结果自行补业务语义。

## 2. Stitch 标准流程

本项目固定使用以下流程：

1. `create_project`：建立私有的全站产品设计项目。
2. `upload_design_md`：上传经产品评审的设计原则、布局、颜色、字体、组件和状态要求。
3. `create_design_system_from_design_md`：生成统一设计系统，不允许每个页面各自发明样式。
4. `generate_screen_from_text`：按页面族逐个生成主状态，不一次要求模型生成全站。
5. `generate_variants`：只为会改变流程或布局的状态生成代表变体。
6. `edit_screens`：根据产品评审逐屏修订，不通过反复生成随机替代方案碰运气。
7. `get_screen`、`list_screens`：逐屏检查尺寸、结构、文案、状态和设计系统一致性。
8. `apply_design_system`：设计系统调整后统一回灌选定页面，避免局部漂移。

生成超时不得立即重复调用。先按 Stitch 工具约定轮询已有 screen，避免同一页面被重复生成。

## 3. 商业设计原则

- 1A 第一入口必须是对话 Agent，不得出现画布优先、营销首页或通用后台首页。
- 主应用采用安静、专业、适合高频电商运营的浅色工作台；阶段 3 画布可使用独立深色专业模式，但不得把全站做成暗色霓虹工具。
- 视觉层级以任务、商品、图片结果和可执行动作优先，不用大标题、装饰性渐变、光球或无业务价值的大卡片。
- 靛蓝主色 `#2F49DF` 只用于明确动作；积分和费用使用独立琥珀 `#B56A18`；青绿 `#087B75` 用于信息/成功辅助语义；阻断和危险使用珊瑚红。状态不能只靠颜色表达。
- 页面标题 32-40px、分区标题 20-24px；正文以 16px 为基准、最低 15px；操作标签最低 14px。12-13px 只允许用于非关键元数据并满足对比度，关键操作和错误不得使用微小灰字。
- 圆角不超过 8px。按钮、输入框、菜单、抽屉和表格保持稳定尺寸，动态内容不能造成布局跳动。
- 图标使用熟悉的 Lucide 语义；不熟悉的图标必须有 tooltip。模式切换使用 segmented control，选项集合使用 menu，二元设置使用 checkbox/toggle，数量使用 stepper。
- 页面语言以中文为主；不得显示内部枚举、tool JSON、Provider 原始错误、完整 prompt、账本事件或对象存储键。
- 不复制参考产品的品牌、布局像素或视觉装饰，只复用已验证的交互模式和信息架构。

## 4. 全站信息架构

### 4.0 进入产品后的真实路径

产品不是后台管理台，也不是营销首页。入口和主路径固定如下：

| 场景                          | 进入页面                     | 首屏行为                                                      |
| ----------------------------- | ---------------------------- | ------------------------------------------------------------- |
| 未登录访问 `/`                | A04 `/` 访客创作首页         | 直接看到中文电商创作输入区；提交指令时打开 A01 登录弹层       |
| 未登录访问受保护页面          | A01 回退页或登录弹层         | 登录、注册/邀请码、找回入口；完成后回到原目标                 |
| 已登录访问 `/`                | A04 `/` 创作首页             | 显示创作输入区；提交后创建会话并进入 `/workspace/session/:id` |
| 已登录点击主导航“创作”        | A04 `/` 创作首页             | 始终回到创作首页，不进入空白会话路由                          |
| 从会话栏点击“新对话”          | A04 `/workspace/session/new` | 进入会话区空白态，尚未创建具体会话                            |
| 从商品/作品/参考图发起创作    | A04 `/workspace/session/new` | 携带明确上下文进入会话区空白态，发送后进入具体会话            |
| 已登录从历史会话进入          | A04 `/workspace/session/:id` | 恢复消息、附件、任务和产物，不重新创建 turn/run               |
| 从 A04 选择商品               | A05/A06                      | 选择或建立商品/SKU，返回原会话继续创作                        |
| 从 A04 查看资产/作品/任务     | A07/A08/A09                  | 完成操作后返回原会话或原商品上下文                            |
| 2B 开放后从 A04 选择套图入口  | B09 `/suites/new`            | 商品/SKU 驱动的分步套图配置，完成后回到套图结果或 A04         |
| 3a 开放后从产物或导航进入画布 | C01/C02                      | 明确“送入画布”后进入手工画布；不把 A04 对话自动变成画布       |

全局“返回”必须回到真实来源上下文，例如从商品选择器回 A04 当前输入，而不是统一跳首页。创建、改图、积分核对失败、下载和送入画布都必须有明确完成/取消/失败出口。

### 4.1 全站应用壳冻结规则

普通业务页面（A01-A10、B01-B09）共享一套壳，不允许 Stitch 每屏重新设计顶部栏或左侧栏。壳参考即梦线上产品的“稳定窄主导航 + 创作区优先”骨架，并结合蛙创的会话恢复能力：

- **顶部区域**：不使用后台式横向菜单。普通页面只保留 64px 内的轻量工具区：当前页面/上下文在左，积分余额、全局任务、帮助和账号在右。站内通知随 S16 激活；访客态只保留品牌、帮助和“登录”入口。不要放会员营销、OCP、活动倒计时或与当前任务无关的按钮。
- **左侧主导航**：固定 128px 紧凑图标加中文文字栏，品牌在顶部；1A 顺序固定为 `创作`、`商品`、`资产`、`作品`、`任务`；阶段 2 追加 `批量`、`套图`、`发现`，阶段 3 追加 `画布`；底部始终为 `账户`。文字使用 12px，图标辅助识别，不能只留图标让用户猜功能。`新会话` 是创作入口内的主动作，不与全局业务对象混成菜单。正式分阶段发布时未开放功能不显示入口；全站原型开启全部阶段，必须显示画布。
- **会话栏**：仅在 A04 出现。新会话空态默认收起为“历史会话”入口，避免首屏形成后台多栏；进入历史/活跃会话后可展开为 280px 辅助栏，包含新会话、搜索、按时间分组列表和会话操作。
- **普通页面主区**：页面标题、筛选/搜索、主任务区和必要的上下文抽屉。避免把每个业务对象都做成表格后台。
- **A04 新会话主区**：参考成熟创作产品的低摩擦首屏，大面积输入区位于首屏中心；输入区内包含附件、必选主 Skill、当前 Skill 的 Preset、生成参数和发送。1A 只展示已经开放的生图能力，不提前展示视频 Agent。数量使用“常用值 + 可编辑正整数”的紧凑控件，不锁死为少数候选；指令明确写“两张”“生成 6 张”时，Agent 解析值同步到当前 turn 的数量参数和后续确认摘要。商品/SKU 不作为首页固定选择器，只在明确进入电商上下文后由对话或商品流程承接。下方只显示当前 catalog 已发布的白底精修、人像焕新、照片意象重绘等 primary 快捷入口及最近作品，不放数据看板。
- **A04 活跃会话主区**：消息、确认卡和图片结果占主宽度；会话栏按需展开；右侧任务/产物抽屉默认收起，只在生成、结果未知或用户主动打开时出现。
- **C02 专业壳**：进入画布后收起普通主导航，只保留返回、画布标题/保存状态、撤销重做、任务日志和阶段开放的导出/发布；左侧只放画布工具。

普通业务壳使用浅色中文产品界面；C02 才允许独立的深色画布工作区。不得把全站统一成深色霓虹，也不得把普通产品页生成成运营后台仪表盘。

普通用户产品固定为 21 个页面族（A01-A10、B01-B09、C01-C02），不因 Stitch 自动建议而增加或合并。独立管理台 O01-O12 另行计数，S12/S14B 激活内容安全处置后才增加 O13；管理页不共享普通用户壳：

## 5. 第一优先页面：A04 Agent 工作台

### 5.1 桌面结构

1. 全局导航：商品、资产、作品、任务和账户；保持紧凑，不与会话列表混成一层。访客态可输入，但不展示需要登录后才可访问的业务数据。
2. 会话栏：新对话、搜索、会话历史和收起。
3. 中央工作区：消息流、Agent 可见进度、确认卡、结果卡和固定输入区。
4. 输入区：当前输入附件、附件角色、文本输入、`@` 引用、模型/尺寸等可选项、费用预估和发送。
5. 右侧上下文栏：当前会话任务和产物；可收起，不能成为第二个完整任务页面。
6. 结果预览：单张/候选切换、风险信息、继续改图、下载、保存到商品/资产和申诉。

### 5.2 附件和 `@` 规则

- 附件必须先进入当前输入附件栏，才能被 `@` 引用。
- `@` 候选只显示当前输入附件，不搜索整个会话、画布或资产库。
- 历史结果通过“加入本次输入”显式绑定；绑定后保留稳定 attachment/artifact ID。
- 附件支持排序、预览、移除和角色标注；删除、越权或隔离附件在发送前阻断。
- “继续改图”把目标产物加入输入并聚焦输入框，不覆盖原产物。

### 5.3 不允许出现

- 计划步骤确认或自动规划画布。
- 思维链、tool JSON 或内部执行节点。
- 增加任何费用确认框或用户金额上限：所有生成入口的生成/运行按钮本身就是动作授权；服务端必须在 Provider 前报价、核对和预留，失败就地提示。
- 把画布全部节点自动作为附件或 `@` 候选。

## 6. C02 画布编辑器

- 画布是阶段 3 的全屏专业工作区，进入后收起普通业务主导航，并提供明确返回入口。
- 左侧只放画布工具：选择、移动、添加节点和必要资源入口。
- 支持文本、图片和视频节点。节点选中后显示节点上方操作条和节点下方就地输入框。
- 已连接上游节点自动进入该节点的附件区；手动添加附件时创建一个真实上游素材节点和边，不生成隐藏附件关系。
- 节点输入框中的 `@` 只引用该节点附件区，不搜索全画布。
- 单节点和整链执行都先由服务端 compile，再进入报价/确认；画布本身不由 Agent 自动规划。
- 移动端只提供只读、任务和结果查看，不伪装成完整编辑器。

## 7. 状态设计矩阵

每个相关页面必须覆盖：

- 首次加载、空数据、筛选无结果、分页失败和局部重试。
- 上传排队、上传中、处理、成功、类型/大小失败和内容拒绝。
- Agent 输入、思考、澄清、事实确认、Brain 张数解析、积分核对、superseded 和中断。
- 价格不可用、数量越界、余额不足、排队、运行、检查、结果未知、失败、取消和退款。
- 产物可用、warning/unknown、隔离、删除中、已删除和无下载权。
- SSE 正常、重连、watchdog、快照恢复和离线。
- 画布保存中、已保存、离线、revision 冲突、非法边/环、上游未就绪和失效引用。

状态文案使用 `04 §11.1` 的用户视角映射，不直接暴露内部状态。

## 8. 响应式与尺寸

- 桌面主设计基准：1440×900；同时检查 1280×720 和宽屏 1920×1080。
- 移动主设计基准：390×844；同时检查 360×800。
- A04 移动端把会话历史和任务/产物栏收进独立抽屉；输入区始终可达且不遮挡最后一条消息。
- C02 移动端为只读状态，不压缩桌面工具栏形成不可用编辑器。
- 长中文、金额、错误文案、文件名和商品名必须换行或省略，不得溢出、遮挡或改变固定工具尺寸。

## 9. Stitch 生成批次

1. 先生成设计系统展示、A04 访客新会话空态和 A01 登录弹层。
2. 生成 A04 有会话结果态、积分核对/余额不足态、运行/重连态和移动态；不得生成费用卡、执行模式或数量控件。
3. A04 主路径产品评审通过后，生成 A02-A03、A05-A10，并统一应用设计系统；A01 不再作为首屏独立登录页生成。
4. 第一组冻结后，生成 B01-B09 及代表 overlay。
5. 第二组冻结后，生成 C01-C02；C02 单独生成节点选中、输入、运行和冲突代表态。
6. 每组评审只修订现有 screen；除非信息架构变化，不新增页面族。

## 10. 商业评审门禁

每个页面在冻结前必须同时通过：

- 业务完整：主要入口、成功出口、异常出口和返回上下文完整。
- 契约一致：字段、状态、积分核对、权限和阶段归属不与文档冲突。
- 视觉一致：颜色、字体、间距、圆角、组件和图标遵循同一设计系统。
- 操作效率：高频任务不需要重复跳转；危险动作有影响说明和防重复提交。
- 状态完备：空、加载、失败、隔离、重连和恢复不是临时占位。
- 响应式：桌面和移动文字无溢出、控件无重叠，触控目标可用。
- 可实现：布局可用 Next.js、React 和既定组件体系实现，不依赖无法维护的生成代码结构。
- 可验证：对应 SPEC 已列出组件测试或 Playwright 流程。

只有用户明确确认某一组“产品设计评审通过”，该组才视为冻结并允许进入 UI 编码。
