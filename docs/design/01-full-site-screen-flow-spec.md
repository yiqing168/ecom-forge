| 项目     | 内容                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 状态     | v0.1，Stitch 设计前冻结草案                                                    |
| 适用范围 | A01-A10、B01-B09、C01-C02 及其 overlay；独立管理台 O01-O12 另按 S14A/S14B 裁决 |
| 设计原则 | 面向中国电商场景组织商品/SKU、积分核对、权限与创作交互                         |
| 设计依据 | PRD、UI 契约与本文页面规格                                                     |

## 2. 产品主路径

### 2.1 首次访问与登录触发

```text
访问 /
  -> A04 访客态新会话
  -> 输入创作指令、上传附件、在当前附件中使用 @
  -> 点击“开始创作”
  -> 未登录：打开 A01 登录/注册弹层，保留草稿和附件
  -> 登录/注册/邮箱验证完成
  -> 回到 A04，恢复草稿和附件，但不静默发送
  -> 用户再次点击发送
  -> Brain 解析图片张数/工具参数 -> 事实确认（需要时） -> Compiler 报价 -> Credit 核对/预留
  -> reservation + workflow_run 同事务创建 -> 生成 -> 审核 -> 结果
```

- `/login` 是受保护路由和外部深链的回退页，不是未登录用户访问 `/` 的首屏。
- 主导航“创作”始终进入 `/` 创作首页；首页提交后创建会话并进入 `/workspace/session/:id`。
- `/workspace/session/new` 只由会话栏“新对话”和商品、作品、参考图等带上下文创作动作进入，不作为主导航“创作”的目标。
- 登录弹层关闭后，A04 草稿、附件和输入焦点保留；登录成功后不得偷偷重复创建 turn、quote 或 run。
- 登录回流不能自动提交收费动作；用户再次点击生成后才进入 Brain/Compiler。quote、余额核对或 reservation 失败均不得调用图片 Provider。
- 访客态不展示历史会话、商品数据、资产库和余额；顶部只显示品牌、帮助和“登录”。

### 2.2 生成、结果和继续修改

```text
A04 输入
  -> Agent 理解/澄清
  -> 商品事实确认卡（电商任务需要时）
  -> Brain 解析图片张数 -> Compiler 报价 -> Credit 核对/预留
  -> 任务进度和结果卡
  -> 预览 / 下载 / 存入资产 / 关联商品 / 继续改图
  -> 继续改图把目标产物加入当前输入附件，不覆盖原产物
```

### 2.3 专业画布

```text
A04 结果或 A07/A08
  -> 用户明确点击“送入画布”
  -> C01 画布列表或直接打开已有画布
  -> C02 手工创建文本/图片/视频节点和边
  -> 选中节点：上方操作条 + 下方就地输入面板
  -> 单节点/整链 compile -> quote -> 用户确认 -> 队列执行
```

画布不由 Agent 自动规划；连接上游节点才形成附件关系；手动添加附件会创建真实上游节点和边；`@` 只搜索当前节点附件区。

## 3. 全局壳与视觉层级

### 3.1 普通产品壳

- 左侧 128px 紧凑导航：每项同时显示图标和 12px 中文文字；1A 显示品牌、创作、商品、资产、作品、任务；阶段 2 追加批量、套图、发现，阶段 3 追加画布；底部固定账户。全站原型开启全部阶段并显示画布，正式发布再由 feature flag 隐藏未开放入口。
- 顶部 64px 轻工具区：当前上下文在左，积分/全局任务/帮助/账号在右；站内通知随 S16 激活，访客只显示品牌、帮助、登录。
- A04 的会话列表默认收起，活跃会话才展开 280px 会话栏；右侧任务/产物为按需抽屉。
- 主视觉永远是当前创作任务、商品、附件或结果，不是指标卡、运营表格或营销横幅。
- 所有页面中文；内部状态、Provider 原文、完整 prompt、对象存储 key 不出现在 UI。
- 视觉 token 以 `stitch-design-system.md` 为唯一真相：靛蓝 `#2F49DF` 为主动作，青绿 `#087B75` 为信息/成功辅助，琥珀 `#B56A18` 只表达积分与费用。正文以 16px 为基准、最低 15px，操作标签最低 14px；12-13px 只用于非关键元数据。

### 3.2 画布壳

- C02 进入后收起普通导航，使用独立全屏专业工作区。
- 顶部只保留返回、画布名、保存状态、撤销/重做、任务日志和阶段开放的导出/发布。
- 左侧只放画布工具，节点上下文操作不放到全局后台侧栏。

## 4. 逐页规格

每页的“主操作”只有一个视觉主按钮；“返回上下文”必须回到实际来源，不统一跳首页。每页至少实现桌面主态、移动主态、空态、加载态和错误/恢复态；不能通过堆叠卡片替代页面任务。

## 5. 关键交互细节

### 5.1 A04 输入区

1. 文本是主输入；附件以 chip/缩略图进入当前输入附件栏。
2. 上传附件后才进入 `@` 候选；`@` 只列当前输入附件，不列全画布、历史会话或资产库。
3. 从资产库或历史结果选择时，必须点击“加入本次输入”，再出现在当前附件栏。
4. 发送按钮旁显示当前模式和必要的模型/Skill 选择；高级参数放菜单，不占主视觉。图片数量不设控件，由 Brain 从自然语言解析。
5. 访客点击发送先弹 A01；登录成功恢复草稿但不自动发送。已登录才进入 Agent turn。

### 5.2 A04 对话流

- Agent 只输出用户可理解的进度：“正在读取商品图”“正在确认商品信息”“正在准备生成”。
- 必要事实确认和风险提示是消息流中的卡片，不跳独立表单、不增加隐藏确认；A04 不显示费用卡、执行模式或当次积分上限。
- 结果卡提供预览、继续改图、下载、存资产和关联商品；原结果保留，改图生成新结果。

### 5.3 C02 节点

- 选中节点后上方只显示该节点工具条，下方只显示该节点的附件、prompt、参数、费用和执行。
- 连接的上游自动进入附件区；手动添加附件创建真实上游节点和边。
- 节点 `@` 只引用当前节点附件区；画布不会自动规划节点或把全画布变成附件。

## 6. Stitch 生成与淘汰规则

生成顺序固定为：A04 访客空态 -> A01 登录弹层 -> A04 活跃/确认/结果/重连 -> A02/A03 -> 其余 A 组 -> B 组 -> C 组。

以下任一项不合格，标记为废稿并重新编辑/生成，不进入代码：后台管理台式三栏、画布优先、登录先于创作输入、英文主界面、虚构的导航入口、缺少真实成功/失败出口、中文溢出/重叠、把 `@` 扩大为全画布搜索、在 A04 增加费用卡/执行模式/数量控件，或绕过 Provider 调用前的积分核对。

每个主流程代表态先由 Codex 做结构和视觉检查，再交用户评审；用户未验收前不进入正式 UI 编码。
