## 1. 产品概述

### 1.1 产品定位

面向**电商卖家/运营为主、泛创作者兼顾**的 AIGC 创作平台，提供图片与视频的 AI 生成能力，核心覆盖三种创作模式：

1. **对话式 Agent 生成（敏捷生成入口）** — 自然语言对话驱动，**创意与电商生成都承接**，Agent 规划任务、按域加载技能；本会话产物可迭代，电商产物可送入画布深加工
2. **无限画布工作流（专业编排 + 电商修改出口）** — 节点连线式编排的专业生产能力，含**节点内指令式改图**，是既有电商产物修改的唯一出口
3. **商品套图流水线（电商表单快速通道）** — 上传商品图，按平台规范一键批量产出整套电商物料，产物可送入画布继续加工

商业模式：**积分制消耗 + 会员订阅**。阶段 1A 只使用平台发放的封闭内测积分，不接支付，也不展示充值/订阅占位；会员与购买入口按 S21 及后续支付 SPEC 独立开放。

### 1.2 模式边界规则（R1-R5，全文约束）⭐

以下规则为产品全部功能设计的强约束，任何功能归属争议以此表裁决：

| 规则                    | 内容                                                                                                                                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R1**（v1.4 澄清）     | 对话 = **敏捷生成入口**（创意 + 电商生成都接）。仅本会话生产的产物可在该会话内自由迭代、下载、存库、分享；电商产物额外支持"送入画布"                                                                                        |
| **R2**                  | 画布 = 专业编排 + 非对话会话内电商产物的唯一修改出口。纯生产能力，含节点内指令式改图                                                                                                                                        |
| **R3**                  | 套图 = 电商标准出图快速通道。产物可进画布继续加工（电商域内部流转）                                                                                                                                                         |
| **R4**                  | 跨域桥：**创意产物 → 资产库 → 被画布/套图引用**（单向）；对话电商产物 → 画布（域内流转）                                                                                                                                    |
| **R5**（v1.4 可执行化） | **画布/套图产出的既有产物不可拉入对话修改**（修改权归属"谁生的谁负责改"）。系统内产物是否可编辑只按生产入口与修改权元数据判断；LLM 不得决定或绕过该边界。用户新上传的原始素材可作为新会话生成输入，但不被伪装为系统既有产物 |

**产物归属与拦截协议**：每个产物必须持久化 `producer_mode`（`chat|canvas|suite`）、`producer_session_id`（对话产物必填）和 `mutation_owner`（`chat_session|canvas|suite`）。执行器在任何引用、指令编辑或生成前确定性校验：仅 `producer_mode=chat` 且会话 ID 匹配的产物可进入该对话的迭代；画布/套图产物只能走各自所有者或挂载至画布后修改。LLM 只负责解析用户指代和意图，不能用提示词判断产物来源或放行请求。将对话产物作为画布素材引用不会改变原产物的修改权；画布随后生成的下游产物归画布所有。

该协议只适用于携带系统 `artifactId` 的一等产物引用。用户重新上传、下载后再上传或从站外导入的文件均是新的原始素材；平台不得依赖 EXIF、隐写水印或图像相似度猜测其生产入口并据此拦截。此类文件可开启新的生成任务，但不能借此伪造或修改系统内既有产物的历史与归属。

**对外统一话术**（写入产品文案与帮助中心，避免规则被感知为混乱）：

> "本次会话生成的图可以随时继续改；生产线的图回生产线改（可追溯、可批量）。"

### 1.5 核心架构洞察（指导整体设计）

Agent、画布、套图流水线本质是**同一执行引擎的三种外壳**：

- 套图流水线 = 固化的预置工作流
- Agent = LLM 动态规划出的工作流
- 无限画布 = 用户手动编排的工作流

底层统一抽象为 **任务 DAG（有向无环图）+ 工具节点**，三种模式共用：模型网关、任务队列、积分账本、资产存储。真实执行模型必须落为 `workflow_run → task → task_attempt → artifact`，不能只将 DAG JSON 作为唯一执行状态；积分预留、供应商回执、任务重试和产物谱系均挂在该模型上。此抽象是全部技术方案的基石，评审时请重点确认。

### 2.2 积分体系（P0）

#### 2.2.1 积分规则

- 积分为平台唯一消耗货币，所有生成动作按 **模型 × 分辨率 × 时长 × 次数** 计价
- 定价参考量级（最终由模型成本核算后配置在后台）：
  - 图片生成：0.8 ~ 2.7 积分/张
- **指令编辑（v1.1 新增档）**：0.8 ~ 2.0 积分/次 — 本会话产物或画布节点的指令式改图走图像编辑模型，成本接近图生图，**不得按工具价计费**（按工具价会亏损）
  - 视频生成（15s 720p）：约 16 积分/条
  - 工具类（抠图、放大、蒙版局部重绘）：0.2 ~ 0.5 积分/次
- 模板解锁：免费 / 会员免费 / 积分解锁（会员享 5 折）
- 首版积分价格、会员赠送额度和单次调用上限必须基于阶段 0 的真实成本模型决定：记录模型/分辨率/时长/失败重试/存储与流量的单位成本，设定目标毛利与风险准备金后反推积分价值；不得仅按参考量级上线收费

#### 2.2.2 积分账本（核心交易流程）

```
生成请求 → 预估费用（前端展示"预计 X 积分"）
        → 用户确认或任务提交（直执行/免确认任务）→ 冻结积分
        → 任务执行成功 → 结算扣除
        → 任务失败 → 解冻退还（自动，无需人工）
```

- 所有变动记录流水：类型（充值/赠送/消耗/退还）、关联任务、时间、余额快照
- 用户可查看积分明细页（按月筛选、按类型筛选）
- 每次任务提交先创建不可变的积分预留（`reservation`），再创建 `workflow_run`；多步任务按总预估一次冻结，子任务仅从该预留结算，禁止每步重新扣款。所有生成入口都以用户点击生成/运行的幂等动作作为授权证据，不再弹费用确认框
- 每个 `task` 均有稳定幂等键；每次实际投递形成独立 `task_attempt`，保存投递时间、供应商请求 ID、回执状态和原始错误摘要。刷新、重连、重复点击和 Worker 恢复不得创建第二次付费调用
- 供应商状态至少区分：`not_dispatched`（本地确认未送达）、`accepted`（已有供应商回执）、`outcome_unknown`（请求已离开平台但结果未知）。只有 `not_dispatched` 可按 T4 自动重试；其余状态仅允许人工或用户明确发起新动作，并提示重复生成风险；新动作重新报价和预留但不弹费用确认框
- 冻结、结算、解冻、申诉退款和人工冲正必须通过同一服务端事务及幂等键写入账本；`credit_accounts` 是余额投影，`credit_ledger` 是不可篡改审计来源

#### 2.2.3 积分获取（第一期）

- 注册奖励活动和管理员后台手动发放；均受版本、预算、资格、次数、风险和幂等约束
- 每日签到不进入 1A；需要时随 S21 或独立增长 SPEC 评审，不能以硬编码每日发放补额度
- 1A 不展示充值入口、套餐卡片或“即将开放”占位

#### 2.2.4 积分申诉通道（v1.2 新增）

- 适用场景：意图误判导致的错误生成扣费、生成结果严重不符（黑图/花图）、重复扣费争议
- 入口：积分明细页每条消耗流水带"申诉"按钮（任务完成后 72h 内可发起）
- 流程：用户提交理由（可附截图）→ 进入后台审核队列 → 管理员裁决退还/驳回 → 结果通知用户
- 护栏：单用户每月申诉上限（如 10 次）防滥用；申诉退还计入 `credit_ledger` 独立类型（`appeal_refund`），纳入退款率指标监控（§1.6）

#### 2.2.5 积分与权益合规门禁（v1.6 新增）

- 封闭免费内测和公开/付费上线分开治理：封闭内测可发放不可转让的测试额度；公开提供充值、会员赠分、积分解锁或其他付费权益前，必须完成适用法律、退款/终止规则、用户协议和隐私政策的专业法务审查
- 平台不得仅以“虚拟道具”命名规避对积分的法定义务。积分是否可购买、是否过期、服务终止时如何处理、是否可转让或兑现，须以经审查的产品政策和协议为准
- 所有用户对上传素材真实性、授权范围和商品事实负责；平台对任务、风险提示、用户确认和申诉裁决保留可审计记录，但用户确认不替代平台应履行的内容安全与合规义务

### 2.4 对话式 Agent 生成（P0，敏捷生成入口，核心差异点）

> 遵循 R1/R5（v1.4）：对话承接**创意与电商的从零生成**，会话内闭环迭代；系统按产物元数据拦截既有画布/套图产物进入对话修改（修改权归属"谁生的谁负责改"）。

#### 2.4.1 交互形态

参考 WaClaw：左侧会话列表，中间对话流，右侧**任务监控面板**。

- **输入区**：主 Skill 选择器（必选）+ 文本框 + 附件上传 + `@` 引用当前输入区已绑定附件（@图片1；资产或历史产物必须先显式加入本次输入）+ `/` 唤起同一 Skill 选择器。阶段 1A 只允许已验证图片附件，最多 10 个；视频附件随 S16 的资产处理和安全契约一起开放。未选择主 Skill 时发送按钮禁用；快捷入口点击等同于用户选择对应 Skill。会话可保留上次选择供下一 turn 使用，但每次请求都必须显式携带并由服务端重新校验
- **模型控制**：创作端不展示 Provider、Key、endpoint、内部 model ID 或真实成本；阶段 1A 用户只选择后台已发布的产品化推理和图片模型，S16 激活后才增加视频模型。服务端按所选 catalog entry、Skill 能力需求、环境门禁、预算和可用性再次裁决并固定精确模型/价格快照；配置、轮换、停用和审计只在独立管理台完成
- **需求解析按域分深浅**（v1.2 修订）：
  - **电商生成请求** → 输出结构化解析供确认：品类 / 场景（如淘宝主图模特图 6 张）/ 目标平台 / 输入素材说明（如种子图→裂变链路）/ 特殊要求 / 商品事实确认 — 电商出图规格严、返工贵，确认一步值得
  - **商品事实确认是解析确认的子步骤**：调用方根据 Skill 声明所需事实集；1A 白底精修默认只确认商品身份与可见文字，颜色/材质/结构等仅在任务需要或用户提供时纳入，不为凑字段强行追问
  - **创意生成请求** → 不强制确认，直接执行（保持敏捷体验）；仅在关键参数缺失（数量/比例）时轻量追问
- **任务规划与执行**：
  - Agent 生成待办清单（3-6 步），右侧面板实时展示，逐项打勾
  - 每步执行前展示所调用的工具与预估积分；总预估超过阈值（如 20 积分）需用户确认后再执行
  - **电商多步技能（如裂变 6 张）的总预估必须在规划完成时一次算清**（含全部裂变张数），不允许边跑边加价（T2 补充条款）
  - 对话流内嵌"已执行 N 个步骤"可展开查看细节
- **生成动作与积分核对语义**（v1.11 修订）：所有生图入口都不显示费用卡或二次确认框。用户点击生成/运行即授权当前幂等动作；服务端形成完整计划和 quote 后，在 Provider 前核对价格、余额、并发和预留。预计积分可在配置区或运行进度中展示，但不能成为第二次点击；计划、价格或输入漂移时当前动作失败，用户修正后重新点击生成
- **产物面板**（v1.10 阶段边界）：右侧列出所有产物（缩略图 + 命名）。阶段 1A 的创意与电商产物都只显示预览、下载、存入资产库和本会话继续改；S19 后创意产物才显示生成分享页，S24 后符合边界的电商产物才显示“送入画布”
- **多轮迭代**：本会话产物（**含电商图**）可自由对话迭代（"去掉吊牌""背景调暖"）；外部画布/套图产物不可拖入（R5 收窄版红线）
- **做同款**：S20 配方模板契约完成后才开放；阶段 1A 不显示入口。开放时只能复制公开安全配方到新会话并要求替换用户素材，不能泄露原 prompt、私有输入或继承修改权

#### 2.4.2 意图路由（v1.2 反转：从"劝走"变"执行"）

Agent 不额外启动前置分类 LLM；意图证据由使用用户所选主 Skill 的正常 Agent Brain step 产出。该 step 的 token 计入平台成本，但不作为一个独立的用户收费项目。路由目标是在所选 Skill 边界内理解需求并直接工作，仅一种情况引导离开：

| 用户输入                                      | Agent 行为                                                                                                                  |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| "帮我做张淘宝主图 / 白底精修图 / 商品视频"    | 使用用户已选的对应电商 Skill，走解析确认 → 规划 → 生成；所选 Skill 与指令明显不匹配时先提示用户切换，不静默替换             |
| "生成一套详情页 / 整套主图物料"               | 直接执行（阶段 2B 起，依赖规范引擎 §2.13）；同时提示"整套勾选式出图可用套图流水线更快"                                      |
| "把这张图的吊牌去掉"（**本会话产物**）        | 直接执行指令编辑迭代                                                                                                        |
| "把这张主图改一下"（**系统内画布/套图产物**） | **只引导、绝不执行生成**：服务端在执行前按 `mutation_owner` 拦截；回复承接话术 + 跳转卡片（→ 画布，产物自动挂载为素材节点） |
| 新上传商品原图                                | 作为新会话的原始输入，可执行白底精修、从零生成等新产物；不按“外部既有产物”推断其修改权                                      |
| 模糊请求（"把商品拍好看点"）                  | 先追问用途，再按上述路由                                                                                                    |
| 纯创意请求                                    | 直接执行                                                                                                                    |

- **误判兜底**（v1.8）：Agent 理解错误导致的已扣费任务，用户可发起积分申诉（§2.2.4）；系统内非会话产物的修改请求由服务端硬拦截，LLM 的理解结论不能放行该操作
- 引导话术运营可配置；跳转携带上下文（素材、描述），到达目标模块后免重复输入

#### 2.4.3 Skill（技能）机制（v1.8 主 Skill 必选）

- Skill 是版本化知识包：`{ 名称, 描述, 分类, 域标记, planning view, 所需事实, 能力依赖提示, Preset, 辅助知识依赖, references, version }`。它补充方法、审美、SOP 和风险边界，不携带 Provider Key，不选择模型，不拥有可执行 DAG、价格或工具授权
- `creative`、`commerce` 是前端目录分组，不是可执行 Skill。用户每个 turn 必须选择一个 published、当前阶段可用的主 Skill；Agent 不得自动选择、卸载、换版或用另一个主 Skill代替
- 风格 1/2/3、棚拍/生活方式等同一任务内的变体建模为主 Skill 下的版本化 Preset。Preset 只改变知识或审美方向，不增加工具权限；用户所选 Preset 与主 Skill 一起固定快照
- 可复用的类目、真人摄影、平台合规和信息编排知识建模为辅助 Skill。必需依赖由 runtime 在首次模型调用前预载；可选依赖只能由 Agent 从主 Skill 声明的精确版本一跳白名单中按需加载，禁止任意跨 Skill 搜索和递归依赖
- 前端 Skill 目录来自服务端安全 catalog，不硬编码版本。catalog 只返回 published 的名称、说明、分类、预设和安全展示元数据；创建 turn 时服务端必须重新校验，不能信任前端缓存
- **1A 创意 primary（10 个，全部在 S15 前交付）**：
  1. **自由创作** — 承接纯文本或可选参考图的通用从零生图；不以“万能 Skill”绕过专门任务的素材职责和安全边界
  2. **人像焕新** — 在用户授权照片上改善构图、光线、现场感和表现质量，严格固定身份与允许变化边界
  3. **照片意象重绘** — 只提取照片的语义、关系与情绪，重新创作不保留原像素的作品
  4. **实景拼贴** — 将用户授权照片作为可辨识、自然可信的摄影锚点，再以源生插画、结构性色彩和纸面边界进行原创视觉组织
  5. **实景拼贴·写意纸境** — 保留授权照片中的实景锚点与空间关系，以画面之势、实虚转折、单一纸墨行为和方向性留白重组为当代写意纸本作品；默认不生成题字、印章或国潮符号
  6. **极简拼贴** — 将授权实景照片转译为严格上下双联的极简纸感孔版印刷海报，由 Provider 一次生成完整成品
  7. **实景转译·日常记忆页** — 从授权生活照片提取单一记忆证据，以连续空场、局部重绘和克制纸本材料形成日常记忆页
  8. **叙事电影海报** — 从原创梗概或授权视觉参考建立唯一母题、构图动作和事实受控的电影海报
  9. **日常反差海报** — 从授权生活素材选择服务同一反差的证据，形成克制、不可伪造事实的单张海报
  10. **虚空线稿** — 将授权原片中最具识别性的主体压缩为小尺度锚点，投入单一运动逻辑的虚空场域，形成上下严格 1:1 的单张极简线稿版画海报；色彩只从原片提取，编号与坐标类文字不得伪造真实身份、地址或数据
- **首版电商类目知识**：商品白底精修 primary 必须可按事实动态加载服饰鞋包、美妆个护、食品饮料、家居生活、宠物用品、运动户外和数码配件 7 个 internal auxiliary，以及真人商品摄影和共享电商视觉知识。类目 auxiliary 不在前端单独选择，不改变工具、模型、价格或权限。
- **共享创作能力**：本会话连续改图不是 primary Skill，而是受 R1-R5、artifact lineage、ToolPolicy 和费用契约约束的共享指令编辑能力；商品创意演绎仍由电商任务路线承接，创意短片归 S16 视频能力，不与图片 primary 混列
- **电商域技能（4 个，按规范引擎依赖分两批）**：

### 2.5 无限画布工作流（P0，分批交付）

> 产品形态硬边界：画布是用户手工创建和连接节点形成的专业工作流，不是 Agent 规划结果。系统不得根据对话自动铺设整张画布，不提供“计划确认”或费用确认步骤；点击运行后由服务端按交易契约完成报价与预留。详细成熟产品证据与采用/拒绝记录见 `docs/research/01-full-site-product-interaction-benchmark.md`。

#### 2.5.1 画布核心

- 基于成熟节点编辑器库（React Flow）实现，**不自研画布引擎**
- 节点类型：
  - **素材节点**：图片、视频、音频（本地上传 / 从资产库选择）
  - **文本节点**：提示词/备注，双击编辑
  - **生成节点**：图片节点、视频节点（承载生成结果，显示尺寸标签如 2048×2048）
  - **应用节点**：封装的子流程（P2）
  - **便签**：画布注释（支持富文本与链接），不参与执行
- 连线驱动：上游输出作为下游输入；支持一对多（1 张种子图 → 6 张裂变图）与多对一（多图 @ 引用合成）
- 显式依赖：一条合法上游边建立后，上游输出自动进入目标节点的附件条；从附件条手动上传或选资产时，必须先创建可见素材节点并建立边，不允许只创建隐藏附件
- 输入顺序：多个输入存在语义顺序时，用户可在附件条拖动排序；顺序持久化在输入槽/边元数据中，不按节点屏幕位置推断
- `@` 只用于引用**当前选中目标节点的附件集合**；不得搜索全画布、其他节点、会话历史或资产库，也不得绕过连线建立隐式依赖

#### 2.5.2 节点操作

- 单选节点后显示两层就地控制，不以右侧固定属性栏替代：
  - **节点上方上下文工具条**：快捷操作随文本/图片/视频节点变化；图片节点包含图片分析 / 背景去除 / 聚焦（蒙版局部重绘，P2）/ **指令编辑** / 下载 / 存资产 / 预览 / 替换图片
  - **节点下方上下文面板**：只属于当前单选节点，包含有序附件条、提示词、模型、尺寸/比例/时长、生成次数、实时积分预估和执行按钮；它不是读取全画布的 Agent 命令栏
- 多选节点不叠加多个单节点工具条和生成面板，只显示对齐、分布、复制、删除等共同操作；相同类型节点的批量参数编辑后置到 3b 评估
- 附件条规则：
  - 连入当前节点的上游自动成为附件，删除附件只删除对应输入边，不删除上游节点
  - “添加附件”上传文件或选择资产后，在目标节点左侧创建素材节点并连线
  - 附件可预览、按语义排序和移除；持久化引用使用 edge/source node/artifact ID，`@图片1` 等序号只作显示
  - 连接删除、源节点不可用、版本回退或权限变化造成引用失效时，执行前必须阻断并定位问题附件
- 处理中节点允许继续连线搭图，但目标节点执行时必须校验所有必需上游是否就绪；不得静默采用上游旧版本
- 节点用户状态统一为未配置 / 可运行 / 排队中 / 生成中 / 检查中 / 成功 / 失败或需处理，不直接暴露 attempt 内部状态

#### 2.5.2a 节点指令编辑与版本历史（v1.1 新增，选项 B 直接成本）⭐

R2/R5 下，"把背景调暖""去掉吊牌"等高频电商改图需求**全部由画布节点承接**，因此节点必须自带完整的指令式编辑能力：

**指令编辑入口**

- 与"重新生成"是**两个独立动作**，用户心智不同：
  - **重新生成**：沿用当前参数重跑，产出新候选
  - **指令编辑**：输入自然语言指令（"把吊牌去掉，只保留手链"），调用图像编辑模型在当前图基础上修改
- 编辑入口位于节点上方工具条 + 节点右键菜单；触发后复用该节点下方上下文面板并切换到“指令编辑”模式，不另造与附件、模型和费用脱节的轻量弹框
- 编辑执行前展示**积分预估**（指令编辑档，§2.2.1）
- 模型路线（T-B1 决策）：**第一期采用指令式整图编辑**（Kontext / Nano Banana 类，体验优先）；蒙版 inpainting 作为"聚焦"工具后置到 P2

**节点版本历史**

- 每次 生成 / 指令编辑 / 替换图片 产生一个**节点版本**，记录：产物、参数快照、来源动作、时间
- 节点上显示版本角标（如 v3），点击展开版本条：缩略图横排，支持**任意版本回退**与**两版本并排对比**
- 版本保留策略：每节点最多保留 20 个版本，超出后最旧版本仅保留元数据（产物文件按存储策略归档）
- 版本数据同时服务"做同款"的链路还原（§2.7）

#### 2.5.3 画布管理

- 我的画布列表：按日期分组（今天/昨天/更早）、缩略图、新建、复制副本、重命名、删除
- 画布数据 = 节点图 JSON，自动保存
- 顶部工具栏：主题切换、积分余额、导出（画布内产物打包）、任务日志（本画布所有生成任务的状态流水）
- 底部工具栏：小地图、对齐、缩放比例、撤销/重做
- 保存状态：画布采用本地即时更新 + 防抖自动保存 + 服务端 revision；顶栏显示保存中 / 已保存 / 离线 / 冲突，多标签冲突时停止覆盖并提供刷新或复制副本
- 移动端：阶段 3a/3b 仅提供画布查看、任务状态、产物预览和下载，不承诺拖线与完整节点编排
- 画布可发布为模板（进入模板市场，P1）

### 2.6 商品套图流水线（P0）

参考 [DesignKit 商品套图](https://www.designkit.cn/product-kit/) 与美图设计室的成熟表单式流程；只采用交互顺序，不复制品牌视觉和专有文案：

1. **上传商品原图**：同一商品 1-6 张
2. **选择参考图（v1.1 新增，R4 落地）**：可**从资产库选择风格参考图**（含对话创意域存入的产物），作为套图风格学习素材 — 这是"创意反哺电商"链路的入口
3. **生成设置**：目标平台（淘宝/天猫/亚马逊/TikTok/Temu…）、国家、语言、比例（1:1 / 3:4 / 16:9）
4. **商品事实与证据**（v1.4 新增）：从商品原图与用户资料提取颜色、材质、Logo、包装可见文字、规格和结构等候选事实，用户可确认、纠正或留空；未知事实不得补造。涉及包装文字、型号、Logo 或特定结构的画面必须将对应原图作为必需参考。事实记录与原图版本一并进入任务快照
5. **商品卖点 & 要求**：结构化引导（产品名称/核心卖点/适用人群/期望场景/具体参数）+ **AI 帮写**按钮
6. **套图结构配置**：
   - 快速预设：主图单张、极简 3 图、平台标准套图和 A+/详情页模式；用户只需主图时不进入 14 类图的高级配置
   - 智能匹配（默认建议，不自动执行）：AI 分析商品图后推荐预设或图类型，必须展示计划张数、每张用途、总积分预估和商品事实风险；用户可修改配置，点击“一键生成”即提交，不增加费用确认框
   - 高级手动勾选：首屏主视觉、核心卖点图、使用场景图、多角度图、场景氛围图、商品细节图、品牌故事图、尺寸/容量/尺码图、效果对比图、详细规格/参数表、工艺制作图、配件/赠品图、系列展示图、商品成分图
7. **一键生成**：整套图（含张数与总积分预估）+ 商品上架文案
8. **产物动作（v1.1 新增，R3 落地）**：每张产物支持 下载 / 存资产库 / **送入画布加工** —
   - "送入画布"将产物挂载为**新画布（或指定已有画布）中的素材节点**，携带来源信息（套图任务 ID + 原始参数），用户在画布中用指令编辑继续修改（如"背景调暖"）
   - 这是选项 B 下电商产物**唯一的修改出口**，属必需流转，不可后置
9. **A+/详情页模式（v1.2 拆分说明）**：A+ 内容（亚马逊规范模块图）与国内详情长图是两套规范与画幅逻辑，产品内拆为两个子模式，共用规范引擎（§2.13）不同规则集
10. **文案声明安全层（v1.2 新增，v1.7 排期同步）**：AI 产出的卖点文案与上架文案，输出前经**文本禁用词库**校验（阶段 2B，校验对象为纯文本字符串，无 OCR 依赖）；图上文字的 OCR 核对（阶段 3+，§2.13.3）复用同一词库。涉及功效类表述（美妆/母婴/食品）自动附"需人工核实"警示标记，用户确认后方可导出
11. **商品保真校验**（v1.7 更新）：输出侧将商品身份、颜色、Logo、包装文字、可见结构与已确认事实及必需参考图进行比对。2B 的校准版本仅对与已确认商品事实存在确定冲突的结果执行 `hard_block`；高风险结果记录用户确认，证据不足时标记“未知”。除硬拦截外不自动丢弃或重试；用户确认后方可作为上架素材导出。内容安全与平台禁用项由 §2.11 的独立审核链路负责硬拦截，不由保真校验器重复判定
12. 批量托管（会员特权，P2）：多商品排队夜间批量生成

### 2.7 模板市场（阶段 2A 基础版）

- **入口结构**：精选模板 / 我的画布 双 Tab
- **分类**（v1.2：移除"医疗健康"，该类目广告合规风险高，暂不承接）：服装鞋包、美妆护理、珠宝首饰、母婴用品、海外电商、宠物带货、剧情带货、创意应用、美景旅游、美味食品、数码家电、汽车用品、家具家装、贴身内衣、童装带货
- **模板卡片**：封面（图/视频预览）、名称、分类标签、解锁方式角标（上新/会员免费/官方/N 积分解锁）、作者、浏览/使用/点赞数
- **解锁方式筛选**：全部 / 免费解锁 / 会员免费 / 积分解锁 / 已解锁；会员享 5 折（如 5 积分 → 2.5 积分）
- **做同款**：解锁后一键复刻 — 画布类模板复制整条链路到我的画布；配方类模板带参数进入 Agent 会话或套图流程，用户只需替换自己的素材
- **搜索**：按关键词搜索灵感或模板
- 模板市场首发仅官方配方模板（运营上传）；UGC 投稿与分成机制 P3，画布模板随 3b 开放

### 2.8 资产与作品（P0）

- **我的资产**：阶段 1A 为图片素材库，支持上传、搜索、预览、删除和供当前 turn 显式选择；视频/音频资产和文件夹管理随 S18 等后续资产组织能力开放，1A 不显示文件夹入口或 `folder_id` 操作
- **我的作品**：全部生成产物，按时间/类型/来源模式筛选；每个作品保留生成参数快照，为 S20 后经授权的“做同款”保留来源，但阶段 1A 不显示该动作
- 存储：本地开发使用本地文件系统；面向中国用户的内测/生产默认使用腾讯云 COS 或阿里云 OSS 私有桶；海外部署可选 Vercel Blob/S3。单文件上限 20MB（图）/ 200MB（视频）。前端访问通过经授权的短期签名 URL 或同等服务端代理，不暴露可长期猜测的原始对象 URL
- 分享页只能公开被用户明确选择的创意产物；分享撤回后立即停止新访问。用户删除资产或账户时，产物、缩略图、派生引用和对象存储清理须遵守明确的保留与删除策略
- 免费/会员存储配额、版本保留数量和归档/物理删除时间由阶段 0 的真实存储与流量成本决定并后台可配置；不在未核算成本前承诺固定大容量或永久保存

### 2.9 任务系统（P0，底层支撑）

- 所有生成为**异步任务**：排队中 → 生成中（进度）→ 成功 / 失败
- 任务队列基于可恢复的 Workflow 引擎；**重试规则以 §8.2 T4 为准（v1.3 修正）**：仅"确定未送达供应商"的失败才自动重试（最多 2 次）且不重复计费；供应商已受理但结果超时的任务不自动重试，由人工/用户触发。最终失败自动退还冻结积分
- 执行状态以 `workflow_run → task → task_attempt → artifact` 为准，`dag_json` 只保存可审计的计划快照而不是运行时真相。任务尝试、回执、积分预留、模型/Skill/规范版本和产物谱系必须可由任务日志追溯
- 前端实时状态：轮询或 SSE 推送；页面关闭后任务继续，回来可见结果
- 任务日志页：任务 ID、类型、模型、消耗、状态、耗时、失败原因
- 阶段 0 起记录并告警：生成成功率、平均/分位等待时长、供应商错误率、回执未知率、积分账本不一致、单位任务成本和单小时总成本；模型或任务异常达到阈值时支持熔断与停止新任务
- 阶段 1A 使用白名单/邀请码和功能开关灰度发布；每个阶段必须定义放量门槛、回滚条件和紧急关闭路径，不以全量上线替代内测验证

### 2.10 统一模型网关（P0，底层支撑）

- **模型注册表**（后台可配置）：模型 ID、供应商、能力（文生图/图生图/图生视频/工具）、支持的尺寸与时长、最大参考图数量、编辑能力、回执能力、单价（积分）、版本、状态（上/下线）
- **适配器模式**：
  - 国内模型优先（即梦、可灵、通义万相、火山、百度等）：各家 API 适配器，需配置对应 API Key
  - 海外模型备选：经 S14 服务端批准的 relay channel 和精确协议 adapter 接入，必须验证中国访问延迟、可用性、成本和合规
- 统一入参出参：三种创作模式均只面向网关调用，不感知具体供应商
- 路由策略：创作端选择产品化 model catalog entry，不选择 Provider 或内部精确 model ID；服务端将其解析到已审批模型快照，再按用户所选主 Skill 的能力需求、预算、可用性和风控策略确定可执行路由。Skill/Agent 只能声明能力需求，不能指定 Provider、Key、替换用户选择或绕过模型准入
- 降级策略：模型不可用时提示切换，不静默换模型（避免计价争议）
- 阶段 0 核验每个供应商的实名/企业资质、地区限制、调用配额、并发/速率限制、内容审核和封禁政策；能力注册表保存配额与可用区状态，网关支持熔断和人工切换，但不在用户不知情时热切换计价或模型
- 阶段 0 必须以真实调用验证首个图片模型和指令编辑模型的参考图、编辑、异步回执、错误分类、真实成本和输出保真；未通过能力契约的模型不得进入可收费路由

### 2.11 内容安全与合规（P0 基线）

- 生成前提示词审核 + 生成后图像审核（接入内容安全 API，供应商待定）
- 真人换脸/换装类能力默认关闭，开放前需肖像权确认流程（P2 讨论）
- 1A 不生成产品水印、不向导出文件写入 AI 标识；内部仍保留模型、时间、lineage 与审核记录
- 用户协议与隐私政策页面
- 注册奖励、邀请奖励和免费生成必须具备邮箱验证、速率限制、可配置奖励上限、风险标记和总开关；异常账户不得自动获得可消费积分
- 生成内容的归属、商用使用范围、用户上传素材授权、模板投稿/做同款许可、供应商模型条款和争议处理必须写入用户协议/模板协议，并在公开或付费上线前完成专业法务审查；PRD 不预设未经审查的版权归属结论

### 2.12 最小运营能力（P0）与管理后台（P1）

阶段 1A 在前台生图闭环前先由 S14A 交付独立管理员登录/MFA/permission、邀请码、Provider/Storage Key、Brain/图片模型目录、规格积分定价和最小审计；真实生图闭环完成后、S15 上线前再由 S14B 补齐用户/风险、任务、账本/申诉/奖励、Skill 发布、管理员安全和审计健康。高风险操作不得依赖直接修改数据库或未经审计的命令行；内容安全审核队列由 S12 管线激活后挂载。

- 用户管理：查询、封禁、手动发放积分；会员手工授予/撤销归 S21，1A 不显示会员入口
- 模型管理：注册表增改、价格调整、上下线
- 技能管理：上传、编辑、验证、审批、上下架和版本回滚；模板管理归 S20，1A 不显示模板入口
- 数据看板：DAU、生成量、积分消耗、模型成本、失败率
- 内容审核队列 + **积分申诉审核队列**（§2.2.4）
- 规范知识库维护归 S23；1A 只保留商品事实与保真 warning/unknown，不显示规范维护入口

### 2.13 平台规范引擎（P0 架构预留 / 阶段 2B 交付，v1.2 新增整节）⭐

> v1.2 起，"平台规范"的约束对象从 1 条链路（套图）扩展为 3 条（套图 / 对话电商技能 / 画布），规范引擎必须设计为**共享底层组件**，位于模型网关旁的独立服务层，属阻断级必做项。商品 SKU 保真不是平台规范：它由独立的商品事实与保真校验器承载，两者可被同一任务组合调用，但不得互相替代。

#### 2.13.1 组成

| 层                               | 职责                       | 说明                                                                                                                                                                                                                |
| -------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 规范知识库                       | 各平台出图规范的结构化存储 | 平台（淘宝/天猫/亚马逊/TikTok/Temu…）× 图类型（主图/详情页/A+）× 规则（尺寸比例、白底要求、主体占比、文字占比、禁用元素、边距） ，后台可维护、可热更新                                                              |
| Prompt 注入层                    | 生成前                     | 将命中的规范规则编译为提示词约束，注入生成请求（三条链路统一走此层）                                                                                                                                                |
| 输出侧校验层                     | 生成后                     | 自动校验：白底检测、主体占比测量、OCR 文案核对（禁用词/夸大宣传）、尺寸合规；不合格产物标记警告并提示重生成                                                                                                         |
| 商品事实与保真校验器（独立组件） | 生成前/后                  | 以用户确认的商品事实和必需参考图为依据，核对 SKU 身份、颜色、材质、Logo、包装文字与可见结构；1A 只输出 `warning/unknown`，2B 校准后对确定冲突输出 `blocked`；高风险确认保留证据快照，不伪装为平台规则，也不自动重试 |

商品事实确认交互由调用方承担：对话将其作为电商解析确认的子步骤，套图将其作为表单步骤。每个 Skill 声明其最小事实集与必需参考图；调用方不得为填满通用字段而增加与任务无关的追问。

商品事实与保真风险按三级处置：2B 校准后的 `hard_block` 用于与已确认事实存在确定冲突的结果；`high_risk_confirmation` 用于高风险但无法可靠判定的结果，须显著提示并以 `risk_confirmations` 记录用户、时间和确认前证据快照；`unknown` 用于证据不足或校验器无可靠结论的结果，只提示未知。法律/平台禁用项由 §2.11 的内容安全链路独立硬拦截。用户确认是审计证据，不构成对平台安全、审核或合规责任的豁免。

规范规则必须带来源、适用平台/国家/图类型、有效期、版本、状态与更新时间。技能、模板、模型和规范均采用发布新版本而非原地覆盖；每个任务快照必须引用实际使用的版本。

#### 2.13.2 调用方

- 套图流水线：全量调用（生成设置中的平台选择即规范知识库查询键）
- 对话电商技能：主图套图 / 详情页技能调用（阶段 2B 与规范引擎同批交付）
- 画布：节点生成面板可选挂载"平台规范"约束（P2）

#### 2.13.3 交付节奏

- 阶段 1A：商品事实记录、必需参考图约束与保真 `warning/unknown` 接口上线；商品事实冲突不自动拦截。平台规范仅落库表结构与服务接口占位，不阻塞白底精修等无规范依赖技能
- 阶段 2B：知识库首批覆盖淘宝/天猫 + 亚马逊 + TikTok 三平台的主图与详情页规则，Prompt 注入 + 白底/尺寸两项输出校验上线；套图和对话电商技能同时接入经校准的保真校验器，并对确定商品事实冲突启用 `hard_block`
- 阶段 3+：主体占比、OCR 文案核对逐步补齐

## 6. 里程碑规划

### 阶段 0 — 架构与交易契约 + Provider PoC（启动门禁）

- 在开始任何可收费功能编码前，完成产物归属/修改权、`workflow_run → task → task_attempt → artifact`、积分预留与账本、供应商回执/幂等、权限与资产访问五项契约
- 用真实 API 跑通 1 个图片模型和 1 个指令编辑模型，验证参考图、编辑、异步回执、错误分类、配额/限流、实际成本与商品保真风险；未通过能力契约的模型不得进入收费路由
- 形成成本表（模型/分辨率/时长/重试/存储/流量）、目标毛利、积分价值和会员赠送上限；成本未核算前只能使用封闭免费测试额度，不开放充值或对外承诺价格
